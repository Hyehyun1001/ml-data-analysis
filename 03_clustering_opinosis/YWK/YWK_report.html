STEP 01 · METHOD

무엇을, 어떻게 분석했나

51개 오피니언 파일을 읽어 소문자화 → 특수문자 제거 → 토큰화 → 불용어 제거 → 표제어 추출(lemmatization)로 정제하고, TF-IDF(1–2gram, 51×4,462)로 벡터화했습니다. 정답 라벨이 없는 비지도 문제라, 실루엣 스코어로 클러스터 수와 알고리즘을 데이터 기반으로 골랐습니다.

코드 보기 — KMeans &amp; 클러스터 해석 
# KMeans로 그룹화 (클러스터 5개로 시작 - 나중에 조정)
from sklearn.cluster import KMeans  # KMeans 임포트

km_cluster = KMeans(n_clusters=5, max_iter=10000, random_state=0, n_init=10)  # 모델 생성
km_cluster.fit(feature_vect)  # 학습(군집화)

document_df['cluster_label'] = km_cluster.labels_  # 클러스터 번호 저장
document_df.sort_values('cluster_label')[['filename', 'cluster_label']]  # 정렬해서 확인

# 각 클러스터의 핵심 단어 + 소속 파일 확인 -> 여기서 클러스터에 "의미"를 붙임
def get_cluster_details(model, data, feature_names, n_clusters, top_n=10, label_col='cluster_label'):  # 상세 정리 함수
    order = model.cluster_centers_.argsort()[:, ::-1]  # 값 큰 순 인덱스
    details = {}  # 결과 딕셔너리
    for i in range(n_clusters):  # 클러스터별 반복
        top_idx = order[i, :top_n]  # 상위 단어 인덱스
        details[i] = {
            'top_features': [feature_names[j] for j in top_idx],  # 단어로 변환
            'filenames': data[data[label_col] == i]['filename'].tolist()  # 소속 파일
        }
    return details  # 반환


feature_names = tfidf_vect.get_feature_names_out()  # 전체 단어 목록
cluster_details = get_cluster_details(km_cluster, document_df, feature_names, 5)  # TF-IDF 기준 조회

for k, v in cluster_details.items():  # 클러스터별 출력
    print(f"=== Cluster {k} (TF-IDF) ===")  # 번호
    print("핵심 단어:", v['top_features'])  # 단어들
    print("파일:", v['filenames'])  # 파일들
    print()  # 빈 줄

STEP 04 · ABLATION

표제어 추출, 전후 비교

전처리에 표제어 추출(lemmatization) 한 줄을 추가하기 전/후로 같은 k-스캔을 다시 돌렸습니다. 최적 클러스터 수는 k=7 → k=8로 바뀌었고, k=2–8 전 구간에서 점수가 대체로 올라갔습니다 — 어휘가 battery/batteries, room/rooms처럼 하나로 정리되면서 클러스터 경계가 더 또렷해진 것으로 보입니다.

적용 전 (원본) 적용 후 (lemmatization)

점선(적용 전)은 k=7에서, 실선(적용 후)은 k=8에서 최고점 — 두 경우 모두 문서 수(51개)까지 늘리면 0.03대로 떨어져 “늘릴수록 좋다”는 아님을 재확인.

결론 — 어떤 모델을, 왜

51개 문서를 빠짐없이 분류해야 하므로, 노이즈를 버리지 않는 알고리즘 중 실루엣 스코어가 가장 높은 쪽을 최종안으로 채택합니다.

● 최종 추천 — Agglomerative Clustering (k=8)

전량 분류 알고리즘(KMeans·Agglomerative·GMM) 중 실루엣 스코어 최고점(0.152). 랜덤 초기화가 없어 완전히 결정론적이라 재현성도 가장 좋습니다.

Agglomerative 채택

  • 클러스터 모양 가정 없음
  • 랜덤성 없음 — 완전히 결정론적
  • 덴드로그램으로 계층 구조 확인 가능
  • k를 미리 정해야 함
  • 데이터 많아지면 연산량 급증(O(n²~n³))

KMeans

  • 빠르고 구현 간단, 대용량에 강함
  • k를 미리 정해야 함
  • 구형 클러스터 가정 — 고차원 희소 데이터엔 약함
  • 랜덤 초기화로 결과가 흔들릴 수 있음

GMM

  • 문서별 소속 확률 제공(소프트 군집화)
  • BIC·AIC로 k 비교 가능
  • 가우시안 분포 가정 — TF-IDF와 안 맞을 수 있음

DBSCAN 부분 채택

  • k를 몰라도 자동 결정
  • 이상치를 노이즈로 자동 분리
  • 문서 20%를 노이즈로 버림
  • eps·min_samples에 결과가 매우 민감

MeanShift 부적합

  • k를 몰라도 자동 결정
  • 고차원 희소 데이터에 매우 취약
  • 이번 데이터에서 전부 한 덩어리로 뭉쳐버림
  • 연산 비용이 커 대용량 부적합

7-1. Agglomerative linkage / metric 튜닝

지금까지는 기본값(linkage='ward', metric='euclidean')만 썼습니다. TF-IDF는 벡터의 방향이 중요한 데이터라 이론적으로는 cosine 거리가 더 잘 맞는다고 알려져 있는데, 실제로 그런지 4×3(일부 조합 제외) 조합을 전부 스캔했습니다.

결과: 기존 기본값(ward+euclidean)이 그대로 최고점(0.1518)이었습니다. cosine이 더 나을 거란 예상과 달리, 이 데이터에서는 원래 설정이 이미 최적이었음을 확인했습니다 — 튜닝이 실패한 게 아니라, "이미 최선을 쓰고 있었다"는 걸 검증한 셈입니다.

metrics = ['euclidean', 'cosine', 'manhattan']  # 시도할 metric 종류

tuning_results = []  # 결과 리스트
for linkage in linkages:  # linkage별 반복
    for metric in metrics:  # metric별 반복
        if linkage == 'ward' and metric != 'euclidean':  # ward는 euclidean만 지원 -> 나머지 조합은 건너뜀
            continue
        model = AgglomerativeClustering(n_clusters=best_k, linkage=linkage, metric=metric)  # 모델 생성
        labels = model.fit_predict(X_dense)  # 학습 + 라벨 예측
        score = silhouette_score(feature_vect, labels)  # 실루엣 스코어 계산
        tuning_results.append({'linkage': linkage, 'metric': metric, 'silhouette': score})  # 결과 저장

tuning_df = pd.DataFrame(tuning_results).sort_values('silhouette', ascending=False).reset_index(drop=True)  # 점수 높은 순 정렬
