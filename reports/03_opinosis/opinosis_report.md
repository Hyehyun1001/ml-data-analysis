## 0. 초록

본 보고서는 UCI Machine Learning Repository가 공개한 *Opinosis* 리뷰 데이터셋(51개 문서, 전자기기·자동차·호텔 3개 도메인)을 대상으로, 비정형 텍스트를 전처리·벡터화한 뒤 비지도 군집화(KMeans, GMM, DBSCAN, HDBSCAN, Agglomerative)로 문서를 토픽별로 자동 분류하는 프로젝트를 정리한 것이다. 팀원 5명(이혜현·이진희·김소현·전유경·권용우)이 각자 독립적인 전처리·벡터화·모델링 파이프라인을 구축해 비교했으며, 동일한 하이퍼파라미터(`ngram_range=(1,2), min_df=0.05, max_df=0.85`)를 설정해도 토크나이저 구현(축약형 처리, 표제어 추출 여부 등) 차이로 최종 피처 수가 파이프라인마다 달랐다는 점이 본 프로젝트의 특징적 발견이었다. 그 결과 김소현의 파이프라인(7단계 Lemmatization + TF-IDF, 51×4,498 희소 행렬)에서 KMeans(k=3)가 **ARI/NMI = 1.0**으로 51개 문서를 도메인과 완전히 일치하게 분류했으며, 이혜현의 54개 파라미터 그리드서치와 전유경의 독립 k=5 파이프라인이 공통적으로 "3대 도메인이 다시 5개 세부 니즈로 갈라진다"는 세분화 구조를 재현했다. 반대로 DBSCAN·HDBSCAN은 51개라는 소규모 데이터셋 특성상 거리 수렴 현상과 노이즈 과다로 부적합함이 세 명의 독립 실험에서 공통 확인되었다. 결론적으로 벡터화 기법(Count vs TF-IDF) 선택이 모델 선택보다 성능에 더 큰 영향을 미쳤으며, 도메인 완전분류(k=3)와 세부 니즈 세분화(k=5)를 병행하는 투-트랙 전략을 최종 제언으로 제시한다.

## 1. 서론

### 1.1 연구 배경 및 필요성

Opinosis는 UCI Machine Learning Repository에서 제공하는 공개 텍스트 데이터셋으로, 아마존 킨들·가민 GPS·넷북 등 전자기기, 혼다·도요타 자동차, 호텔 서비스에 대한 리뷰 문장을 토픽별로 정리한 51개 문서로 구성된다. 각 문서는 "속성_제품명"(예: `battery-life_amazon_kindle`) 형태의 파일명을 가지며, 파일명 자체가 사실상 도메인 정답 라벨 역할을 할 수 있어 비지도 군집화 결과를 검증하는 pseudo-label로 활용할 수 있다는 것이 이 데이터셋의 실용적 특징이다.

정형 데이터와 달리 비정형 텍스트는 정답이 정해진 지도학습 문제로 곧바로 치환되지 않으며, 전처리 방식(표제어 추출, 불용어 제거)과 벡터화 기법(Count vs TF-IDF)에 따라 결과가 크게 달라진다는 점에서, "어떤 선택이 왜 더 나은가"를 데이터로 검증하는 것이 본 프로젝트의 핵심 문제의식이다.

### 1.2 과제 목적

분석 팀은 5명(이혜현, 이진희, 김소현, 전유경, 권용우)으로 구성되었으며, 각자 서로 다른 접근 방식으로 데이터 전처리부터 모델링까지 독립적으로 비교 분석하였다. 본 보고서는 이러한 다양한 시도와 그 결과를 이혜현이 통합하여 정리한 최종 결과물이다.

**중요한 전제**: 다섯 명의 노트북은 겉보기엔 모두 "TF-IDF + KMeans"를 사용했지만, 실제로는 축약형 처리 여부·불용어 사전·표제어 추출 방식(품사 태깅 유무)·`stop_words='english'` 중복 적용 여부 등 토크나이저 구현이 서로 달라 **동일한 `ngram_range=(1,2), min_df=0.05, max_df=0.85`를 설정해도 최종 피처 수가 전부 다르다**(이혜현 4,139개, 김소현 4,498개, 권용우 4,462개 등). 본 보고서는 이 차이를 감추지 않고, 모든 수치·표·그림에 어느 팀원·어느 노트북에서 나온 결과인지 명시한다. 이는 은폐할 한계가 아니라, **서로 다른 5개의 독립적인 파이프라인이 유사한 결론(TF-IDF+KMeans 우위, 3~5개 도메인 구조)에 수렴했다는 교차검증의 근거**로 적극 활용한다.

주요 분석 절차는 (1) 데이터 이해 및 텍스트 EDA, (2) 텍스트 정제 및 표제어 추출(Lemmatization), (3) 텍스트 벡터화 기법 비교(CountVectorizer vs TfidfVectorizer, N-gram), (4) 군집화 모델링 및 비교(KMeans, GMM, DBSCAN), (5) k값 탐색 및 파라미터 민감도 분석, (6) 최종 결론 및 회고 순서로 진행되었으며, 본 보고서 역시 이 흐름을 그대로 따른다.

## 4. 데이터 전처리 및 벡터화

### 4.1 텍스트 전처리 파이프라인

텍스트 전처리는 비정형 데이터를 구조화하는 가장 중요한 단계이다. 5개 노트북 중 가장 상세한 절차를 정립한 것은 **김소현**의 7단계 파이프라인으로, 아래와 같다.

#### 4.1.1 전처리 7단계 프로세스

**<표 4-1> 전처리 7단계 파이프라인** *(김소현 노트북 기준)*

| 단계 | 수행 과업 | 주요 기술 | 산출물 |
|---|---|---|---|
| 1 | 축약형 확장 | isn't → is not, didn't → did not | 정규화된 텍스트 |
| 2 | 소문자 변환 | Battery → battery | 통일된 표기 |
| 3 | 구두점 제거 | 마침표, 쉼표, 느낌표 등 제거 | 정제된 텍스트 |
| 4 | 토큰화 | NLTK word_tokenize 사용 | 단어 리스트 |
| 5 | 순수 숫자 제거 | 26, 96 등 숫자 토큰 제거 | 필터링된 토큰 |
| 6 | 불용어 제거 | the, is, and, not 등 제거 | 의미 토큰만 보존 |
| 7 | 표제어 추출 | batteries → battery, screens → screen | 정규화된 원형 토큰 |

이혜현·김소현·전유경·권용우 4명의 노트북이 공통으로 사용하는 `WordNetLemmatizer()`는 **품사 태깅 없이 기본값(명사 기준, `pos='n'`)** 으로 동작한다. 명사 기준 표제어 추출은 동사 활용형(running→run)이나 형용사 비교급(better→good)을 원형화하지 못하며, 김소현 노트북은 이를 "was → wa"로 잘못 변형되는 사례를 통해 직접 검증하였다.

한편 **이진희의 4개 노트북은 표제어 추출·어간 추출을 전혀 적용하지 않는다**(소문자화 + 정규식 정제 + NLTK 불용어 제거까지만 수행). 그 결과 room/rooms, seat/seats, button/buttons처럼 의미가 같은 단어가 서로 다른 피처로 남아있는데, 이는 표제어 추출 단계를 생략한 파이프라인의 자연스러운 특징이다. 4.2.1절의 이진희 실측 비교는 이 전처리 위에서 이루어졌다는 점을 함께 고려해야 한다.

또한 불용어 제거는 표제어 추출보다 **반드시 먼저** 수행해야 한다. 불용어 사전이 원형(was, does 등) 기준으로 구축돼 있어, 표제어 추출을 먼저 하면 "was → wa"처럼 사전에 없는 형태로 바뀌어 불용어로 걸러지지 않고 남는 문제가 발생하기 때문이다.

#### 4.1.2 전처리 효과 분석

권용우 노트북은 표제어 추출 적용 전/후를 k값별·알고리즘별로 직접 비교(ablation)하였다.

### 4.2 텍스트 벡터화 기법 비교

#### 4.2.1 Count Vectorizer vs TF-IDF 비교

Count Vectorizer는 단순히 단어의 출현 빈도를 세는 방식이지만, TF-IDF는 문서 내 빈도(TF)와 전체 문서에서의 희귀도(IDF)를 함께 고려한다.

![그림 4-4](YW/images/03_count_svd_scatter.png)

*그림 4-4: Count Vectorizer 벡터화 후 SVD 2D 축소 결과 — 클러스터 분리 불명확*

| TF-IDF (k=4) | (18, 15, 10, 8) | 0.067 | 분포는 균형적이나 Silhouette은 오히려 낮음 |

*그림 4-5: TF-IDF+KMeans(k=4) 결과를 PCA 3차원으로 시각화 — Count Vectorizer 대비 문서들이 뚜렷하게 갈라지는 것을 확인할 수 있음*

한편, 6.2절에서 다루는 **김소현의 별도 파이프라인**(7단계 전처리 + TF-IDF, ngram(1,2), min_df=0.05, max_df=0.85, 4,498차원)에서는 KMeans가 **ARI/NMI = 1.00**으로 51개 문서를 도메인과 완전히 일치하게 분류했다(<표 6-2> 참조). 이는 이진희의 비교와는 별개의 노트북·별개의 토크나이저에서 나온 결과이며, TF-IDF의 우수성을 뒷받침하는 독립적인 근거로 함께 제시한다.

#### 4.2.2 초기 TF-IDF 하이퍼파라미터 설정

**<표 4-5> TF-IDF 초기 하이퍼파라미터 설정** *(이혜현 노트북)*

| 파라미터 | 설정값 | 선택 근거 | 효과 |
|---|---|---|---|
| ngram_range | (1, 2) | 단일 단어와 2단어 조합(battery life, gas mileage) 모두 반영 | 복합어 보존 |
| min_df | 0.05 | 전체 문서의 5% 미만 등장 단어 제거 | 노이즈 감소 |
| max_df | 0.85 | 85% 이상 등장하는 일반어 제거 | 도메인 특화 어휘 강조 |
| sublinear_tf | True | 문서 길이 편차(836~12,750) 큰 데이터에 로그 스케일링 적용 | 길이 정규화 |

산출물 규격: **51개 문서 × 4,139개 피처**의 희소 행렬 (LemNormalize 토크나이저 기준. 이 행렬의 희소도는 노트북에 별도로 계산되어 있지 않다 — 6.1절 김소현 파이프라인(51×4,498, 희소도 87.64%)과 혼동하지 않도록 주의)

종합하면, Count Vectorizer 대비 TF-IDF 적용 시 도메인 고유 어휘의 변별력이 뚜렷하게 개선되었으며(4.2.1절), 6.3절의 그리드 탐색을 통해 이혜현 파이프라인은 피처 수를 83% 정제하면서 실루엣 점수를 82% 개선하여 소규모 데이터셋에서 파라미터 최적화의 중요성을 입증하였다.

## 5. 분석방법 (Analysis Method)

### 5.1 전처리·벡터화 필요성 및 과정 개요

EDA(3.1~3.2절)에서 확인한 "불용어가 최빈 단어 상위권을 차지한다"는 문제는 4.1절의 표제어 추출·불용어 제거 파이프라인으로, "Count Vectorizer는 절대 빈도가 큰 단어에 지배된다"는 4.2.1절의 문제는 TF-IDF 가중치 도입으로 직결되었다. 즉 본 프로젝트의 전처리·벡터화 설계는 임의의 관용적 절차가 아니라, EDA에서 실측한 문제를 하나씩 대응해 설계한 결과다.

### 5.2 사용 모델 설명

**<표 5-1> 군집화 모델 선정 이유**

| 모델 | 유형 | 선정 이유 |
|---|---|---|
| KMeans | 중심 기반 | 빠른 수렴과 해석 용이성 — 51개 소규모 데이터셋에 가장 안정적인 베이스라인 |
| Agglomerative | 계층 기반 | 초기값에 비의존적(완전 결정론적)이며 덴드로그램으로 계층 구조를 함께 확인 가능 |
| GMM | 확률 기반(소프트 배정) | 문서가 여러 클러스터에 애매하게 걸칠 수 있다는 가능성을 반영하기 위한 대조군 |

| HDBSCAN | 밀도 기반(계층적) | DBSCAN의 단일 eps 한계를 보완하는 밀도 기반 대안으로서 추가 비교 |

### 5.3 하이퍼파라미터 최적화 기법 설명

이혜현은 `ngram_range × min_df × max_df × n_clusters` 54개 조합을 전수 그리드서치하여 Silhouette Score를 최대화하는 조합을 탐색했다(6.3절). DBSCAN 계열에서는 그리드서치 대신 **k-distance elbow plot**(문서별 k번째 최근접 이웃까지의 거리를 오름차순 정렬한 뒤 꺾이는 지점을 찾는 방법)으로 eps를 결정하는 방식을 전유경이 사용했으며(6.2.5절), 두 방식 모두 "임의로 고른 값"이 아니라 데이터 자체의 구조에서 근거를 도출했다는 공통점이 있다.

### 6.1 차원 축소

TF-IDF 행렬에 TruncatedSVD(n=20)와 PCA(n=20)를 각각 적용한 뒤 동일한 GMM(n=4)을 학습시킨 결과, **두 방식의 클러스터 배정(분포 39:5:4:3)은 완전히 동일했지만 Silhouette 점수는 SVD 0.042 vs PCA 0.121로 약 3배 차이**가 났다. 이는 군집 결과(라벨)가 같아도, 축소된 공간에서 각 문서의 좌표·거리 구조가 달라지면 거리 기반 평가지표(Silhouette)는 다르게 나올 수 있음을 보여주는 사례로, "Silhouette 수치만으로 파이프라인 우열을 단정할 수 없다"는 4.2.1절의 결론과도 일맥상통한다.

#### 6.2.5 DBSCAN 및 밀도 기반 모델 평가

DBSCAN 및 HDBSCAN이 <표 6-2>에서 나타난 바와 같이 상대적으로 낮은 성능(ARI 0.3248, 0.3908)을 보인 것은 51개라는 소규모 텍스트 데이터셋의 특성 때문으로 추정된다. 고차원 텍스트 공간(TF-IDF/LSA)에서는 문서 간 거리가 균일해지는 거리 수렴 현상(distance concentration)이 발생하기 쉽고, 51개라는 적은 샘플 수로는 밀도 기반 알고리즘이 유의미한 코어 포인트를 형성하지 못해 상당수 문서를 노이즈로 분류하는 경향을 보였다. 이 결론은 서로 다른 세 명의 독립적인 DBSCAN 실험에서 공통으로 확인되었다.

## 7. 결과

### 7.1 최종 파이프라인

김소현 파이프라인의 ARI=1.0과 이혜현 그리드서치의 82% 개선(k=5)은 **서로 다른 토크나이저·다른 하이퍼파라미터로 만들어진 별개의 벡터**에서 나온 결과다. 그리드서치 최적 파라미터로 만든 벡터에 k=3 KMeans를 적용해 ARI=1.0이 나온다는 검증은 없으므로, 이 둘을 "하나의 최종 파이프라인"으로 합쳐 제시하지 않고 **목적이 다른 두 갈래(Track) 파이프라인**으로 구분해 제시한다.

| 구분 | Track ① 도메인 완전분류용 (김소현) | Track ② 세부 니즈 세분화용 (이혜현 파라미터 + 전유경 클러스터 실측) |

## 9. 결론

### 9.1 기술적 결론

7단계 표제어 추출 파이프라인은 기본 전처리보다 도메인 특화 단어를 명확히 부각했으나, 4.1.2절에서 확인했듯 그 효과가 모든 알고리즘에 일관되지는 않아 GMM에서는 오히려 소폭 하락했다. TF-IDF는 도메인 고유 특징을 가중하여 CountVectorizer보다 우수한 도메인 구분력을 보였으며(4.2.1절, 실측 근거), 김소현 파이프라인 기준 KMeans(원본 4,498D)는 유일하게 ARI/NMI=1.0으로 완벽한 도메인 분류를 실현했다. 전유경의 별도 파이프라인에서도 KMeans가 가장 안정적이었으나(그림 6-2), 다른 파이프라인에서는 동일한 완전 분류가 재현되지 않았다는 점도 함께 기록해 둔다. 파라미터 최적화 측면에서는 이혜현의 54개 조합 그리드 탐색으로 82% 성능 향상을 달성했으며, 51개 소규모 데이터셋에서는 파라미터 민감도가 높음을 확인했다. N-gram 설정은 비즈니스 키워드 추출 단계에서는 Bigram을, 통계적 최적화 단계에서는 Unigram을 채택하는 실용적 절충안으로 정리했다. 마지막으로 서로 다른 두 벡터(이혜현/전유경)에서 동일한 5-way 세분화 구조가 확인되어, 이 구조가 파라미터의 우연이 아니라 데이터 고유의 특성임을 뒷받침한다(6.4절).

### 9.2 실무적 시사점

복잡한 모델보다 기본적인 거리 기반 알고리즘(KMeans)이 이 데이터에 최적이며, 모델 선택은 데이터 특성에 맞춰야 함을 시사한다(6.2.7절 모델 선택 가이드 참고). 51개 문서는 밀도 기반 알고리즘(DBSCAN/HDBSCAN)에 부적합하며, 세 명의 독립 실험 모두 거리·확률 기반 모델이 더 적합함을 확인했다. 실무 적용 시에는 k=3의 통계적 완벽성(김소현, ARI=1.0)과 k=5의 실무적 세분화(이혜현·전유경)를 투-트랙 전략으로 결합하되, 이들이 하나의 단일 파이프라인이 아니라 서로 독립적으로 검증된 결과라는 점을 반드시 인지해야 한다. 또한 권용우의 linkage/metric 스캔처럼 "바꿔봤지만 원래 설정이 최선이었다"는 결과 역시 유효한 검증이며, 실패로 취급할 필요가 없다.

## 10. 회고

### 10.1 종합 회고

**잘된 점**

5개의 독립적인 파이프라인이 서로 다른 벡터·토크나이저를 사용했음에도 "TF-IDF가 Count보다 우수", "KMeans가 이 데이터에 가장 안정적", "DBSCAN/HDBSCAN은 51개 소규모 데이터에 부적합", "k=5가 3대 도메인을 5개 세부 니즈로 재분할한다" 같은 핵심 결론에 공통으로 수렴했다는 점은 팀 실험 다양성이 만들어낸 강력한 교차검증 성과다. 특히 김소현의 파이프라인은 51개 문서를 도메인과 완벽히 일치(ARI/NMI=1.0)하게 분류해내는 성과를 거두었으며, 이를 k=5 세분화 결과와 결합해 실제 비즈니스에 바로 활용할 수 있는 투-트랙 전략으로 발전시켰다. 또한 어떤 수치·표·그림이든 어느 팀원·어느 노트북에서 나온 결과인지 전 구간에서 명시적으로 추적 가능하도록 관리해, 서로 다른 파이프라인의 결과가 뒤섞여 오귀속되는 것을 방지했다.

**아쉬운 점**

팀원마다 전처리 구현이 조금씩 달라 동일한 하이퍼파라미터를 설정해도 실제로는 서로 다른 벡터가 만들어졌으며, 이 때문에 완전히 동일한 조건에서의 모델 간 비교는 다소 제한적이었다. 팀 공통 함수도 많지 않아 유사한 기능을 팀원별로 각자 구현한 경우가 있었고, 실행 환경(라이브러리 버전)이 고정되지 않아 재현 시 일부 수치가 미세하게 달라질 수 있다는 점도 확인되었다.

**향후 개선 방향**

이혜현의 그리드서치 최적 파라미터를 도메인 완전분류(k=3)에도 실제로 적용해 재현해보면, 지금은 두 갈래로 나뉜 Track①·Track②를 하나의 통합 파이프라인으로 발전시켜 더 강력한 단일 모델을 도출할 수 있을 것으로 기대된다. 또한 권용우가 제안했듯 Word2Vec·BERT 같은 사전학습 임베딩을 함께 시도하면, 51개라는 적은 문서 수와 TF-IDF의 희소성 한계를 넘어 더 정교한 군집 분리를 기대할 수 있다. 마지막으로 제안한 투-트랙 비즈니스 전략을 실제 고객센터 데이터에 파일럿 적용해 KPI를 실측하면, 지금은 방향성만 제시한 제언을 구체적인 성과로 검증할 수 있을 것이다.

### 10.2 팀원별 느낀점 및 피드백


**이혜현 — KMeans / 그리드서치 최적화**

> 정형 데이터와 달리 비정형 텍스트 데이터를 다루며 표제어 추출, N-gram, 불용어 제거 등 전처리 과정의 중요성을 깊이 체감하였다. K-Means, 계층적 군집화, GMM 세 가지 모델이 정답 라벨 없이도 51개 문서를 호텔·자동차·전자기기 세 도메인으로 98% 이상 정확하게 분류해내는 과정을 확인하며 비지도 학습의 강력함을 실감하였다. 특히 고차원 희소 행렬에서 나타나는 실루엣 점수의 한계와, PCA를 통한 2차원 투영이 군집 시각화 및 정량적 평가에서 갖는 필요성을 명확히 이해할 수 있었던 유익한 프로젝트였다.

**이진희 — Count/TF-IDF 비교, DBSCAN/GMM**

> Stemming을 적용하지 않아 room/rooms, seat/seats, button/buttons처럼 의미가 유사한 단어가 서로 다른 피처로 분리되는 현상을 확인하였으며, 이로 인해 문서 간 유사도가 충분히 반영되지 않아 일부 낮은 군집 평가값에 영향을 주었을 가능성이 있다고 보았다. CountVectorizer, TF-IDF, KMeans, GMM, PCA/SVD, DBSCAN 등 다양한 기법을 직접 적용해보면서 각 기법의 특성과 한계를 체감하였으며, 군집 평가에서는 단일 지표만이 아니라 군집 분포·대표 피처·실제 문서 구성 등 정성적 결과를 함께 확인해야 한다는 점을 확인하였다. 또한 KMeans의 군집 수, GMM의 차원축소 방식, DBSCAN의 eps와 같은 파라미터 설정에 따라 결과가 크게 달라질 수 있음을 확인하였으며, 향후에는 전처리와 파라미터 선택의 근거를 보다 체계적으로 설정할 필요가 있다고 느꼈다.

**김소현 — 7단계 전처리 / KMeans 최종 채택 파이프라인**

> 고차원의 희소한 단어-문서 행렬(High-dimensional Sparse Term-document Matrix)이라는 데이터 표현 형태 자체를 이해하는 것이 분석에서 핵심적인 역할을 한다는 점을 깨달았다. 이를 어떤 방식으로 벡터화할 것인가를 고민하며 TF-IDF, PCA, LSA, 임베딩 등 다양한 표현 기법을 비교하게 되었고, 텍스트 분석이 단순 벡터화를 넘어 분류·군집화·의미 기반 검색·추천 등으로 확장될 수 있음을 체감하였다. 또한 이 데이터는 파일명 자체가 사실상 정답 라벨 역할을 할 수 있다는 점에 착안하여, 실루엣 점수(정답 없이 군집 결과와 거리 정보만으로 평가)와 ARI/NMI(파일명 기반 pseudo-label과의 일치도 평가)라는 서로 다른 성격의 두 지표를 함께 활용해야 한다는 것을 배웠다.

**전유경 — KMeans(k=5) / DBSCAN eps 재검증**

> 기존에 다뤘던 정형 데이터(Santander, Creditcard)와 성향이 크게 다른 텍스트 데이터라 초기 접근에 어려움을 겪었으나, 팀 내 공유된 선행 자료를 참고하여 분석 방향을 잡을 수 있었다. Cluster 수를 변화시키며 산점도가 어떻게 달라지는지 시각적으로 확인하는 한편, KMeans 외에 DBSCAN·GMM을 추가로 적용해 각 모델이 데이터에 어떻게 작용하는지 비교하였다. GMM은 KMeans와 거의 동일한 군집 결과를 보인 반면 DBSCAN은 eps 값에 따라 군집 수와 노이즈 문서가 크게 달라졌으며, 처음에는 산점도상 군집이 겹쳐 보인다는 이유만으로 성능을 낮게 판단하였으나 실루엣 점수와 파라미터 민감도까지 함께 확인한 뒤에야 시각화만으로 성능을 단정할 수 없다는 점을 깨달았다. 최종적으로는 해석이 가장 명확한 KMeans(n_clusters=5) 결과를 채택하고 DBSCAN·GMM은 교차 검증 용도로 활용하였으며, 정답이 없는 비지도학습에서는 하나의 지표나 그래프에 의존하기보다 여러 방법으로 반복 검증하는 과정이 중요함을 배웠다.

**권용우 — 5개 알고리즘 종합비교 / 표제어 추출 ablation**

> 기존의 정형 데이터 분석은 명확한 목적과 정답에 가까운 지표를 향해 나아가는 과정이었던 반면, 이번 비정형 텍스트 데이터 분석은 스스로 방향과 목표를 설정해야 했기에 초기 접근에 어려움을 겪었다. 전처리 단계에서부터 산출된 지표를 근거로 의미를 부여하고 해석해 나가야 하는 과정이 쉽지 않았으나, 이 과정에서 스스로 놓치고 있던 개념과 모델 파라미터에 대한 이해도를 높일 수 있었다. 향후에는 외부 사전학습 모델을 함께 적용해 방식의 차이를 비교해보는 방향으로 학습을 이어가고자 한다.

## 12. 부록: 함수코드

아래 함수들은 팀 노트북 5개를 전수 조사한 결과 반복적으로 나타난 패턴(축약형 확장·표제어 추출·클러스터 키워드 추출)을 재사용 가능한 형태로 정리한 것이다(5.5절). 실제 동작 검증은 `Opinosis_최종통합분석.ipynb`(본 reports 폴더)에서 수행했다.

### 12.1 전처리 함수 (김소현의 7단계 파이프라인 기준)

```python
import re
import string
import nltk
from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer

CONTRACTION_MAP = {
    "isn't": "is not", "aren't": "are not", "wasn't": "was not", "weren't": "were not",
    "don't": "do not", "doesn't": "does not", "didn't": "did not",
    "can't": "cannot", "couldn't": "could not", "won't": "will not", "wouldn't": "would not",
    "it's": "it is", "that's": "that is", "i'm": "i am", "we're": "we are", "they're": "they are",
}
_CONTRACTION_PATTERN = re.compile(
    r"\b(" + "|".join(re.escape(k) for k in CONTRACTION_MAP) + r")\b", flags=re.IGNORECASE
)
REMOVE_PUNCT_MAP = dict((ord(p), None) for p in string.punctuation)
STOPWORDS = set(stopwords.words("english"))
lemmatizer = WordNetLemmatizer()


def preprocess_text(text: str) -> list:
    """7단계 전처리: 축약형 확장 -> 소문자화 -> 구두점 제거 -> 토큰화 -> 숫자 제거 -> 불용어 제거 -> 표제어 추출.
    불용어 제거를 표제어 추출보다 반드시 먼저 수행해야 "was -> wa" 같은 오변형을 방지할 수 있다(4.1.1절)."""
    text = _CONTRACTION_PATTERN.sub(lambda m: CONTRACTION_MAP[m.group(0).lower()], text)
    text = text.lower()
    text = text.translate(REMOVE_PUNCT_MAP)
    tokens = word_tokenize(text)
    tokens = [t for t in tokens if not t.isdigit()]
    tokens = [t for t in tokens if t not in STOPWORDS]
    tokens = [lemmatizer.lemmatize(t) for t in tokens]
    return tokens
```

### 12.2 클러스터 해석 함수

이혜현·이진희·전유경·권용우가 각자 다른 이름으로 독립 구현했던 "클러스터별 핵심 키워드 추출" 로직(5.5절)을 하나로 정리한 버전이다.

```python
import numpy as np

def get_cluster_keywords(model, feature_names, top_n=10):
    """KMeans 등 cluster_centers_를 갖는 모델에서, 클러스터별 상위 TF-IDF 단어를 추출한다."""
    order = model.cluster_centers_.argsort()[:, ::-1]
    result = {}
    for c in range(model.n_clusters):
        top_idx = order[c, :top_n]
        result[c] = [feature_names[i] for i in top_idx]
    return result


def print_cluster_summary(document_df, cluster_col, model, feature_names, top_n=10):
    """클러스터별 문서 수·핵심 키워드를 한 번에 출력 (6.2.2절, 6.4절 등에서 반복된 출력 패턴)."""
    keywords = get_cluster_keywords(model, feature_names, top_n)
    for c, kw in keywords.items():
        files = document_df.loc[document_df[cluster_col] == c, "filename"].tolist()
        print(f"[Cluster {c}] ({len(files)}개 문서)")
        print("  핵심 키워드 :", ", ".join(kw))
```

### 12.3 검증 함수

```python
from sklearn.metrics import silhouette_score, adjusted_rand_score, normalized_mutual_info_score

def evaluate_clustering(feature_vect, cluster_labels, category_labels):
    """Silhouette(정답 없는 응집도)과 ARI/NMI(pseudo-label 일치도)를 함께 계산한다(6.2.1절 <표 6-2> 재현).
    두 지표는 서로 다른 질문에 답하므로 항상 함께 보고한다."""
    return {
        "silhouette": silhouette_score(feature_vect, cluster_labels),
        "ari": adjusted_rand_score(category_labels, cluster_labels),
        "nmi": normalized_mutual_info_score(category_labels, cluster_labels),
    }
```
